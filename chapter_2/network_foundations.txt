#Communications Models

We access systems through their address. The problem is that each system will have multiple address. These addresses are best separated into buckets
related to the functionality provided by the protocol each address belongs to.

##Protocols

A protocol is a set of rules or conventions that dictate communication.

##OSI

It includes seven layers. Messages start being created from the Application layer down.

- Application (layer 7): The application layer is the one closest to the end user. This does not mean that it is the application itself, however.
Application layer protocols manage the communication needs of the application. They may identify resources and manage interacting with those
resources. As an example, the HTTP is an application layer protocol. It takes care of negotiating for resources btw client and the server.
- Presentation (layer 6): It's responsible for preparing data for the application layer. It makes sure that the data that is handed up to the
application is in the rght format so it can be consumed.
- Session (layer 5): It manages the communication btw the endpoints when it comes to maintaining the communication of the applications (client and
server). Remote procedure calls (RPCs) are an example of a function at the session layer. There are components of file sharing that also live at
the session layer, since negotiation of communication btw the endpoints needs to take place. It takes care of making sure that files are succesfully
transmitted and complete.
- Transport (layer 4): It takes care of segmenting messages for transmission. It also takes care of multiplexing of the communication. Both the TCP
and the UDP are transport protocols. These protocols use ports for addressing, so receiving systems know which application to pass the traffic to.
- Network (layer 3): It gets message from one endpoint to another. It does this by taking care of addressing and routing. IP is one protocol that
operates at this layer.
- Data Link (layer 2): One other address to contend with is the media access control (MAC) address. This is layer 2 address, identifying the
network interface on the network so communications can get from one system to another on the local network. The Address Resolution Protocol (ARP),
virtual local area networks (VLANs), Ethernet and Frame Relay are Data Link layer protocols. They take care of formatting the data to be sent out on
the transmission medium.
- Physical (layer 1): This is all the protocols that manage the physical communications. 10BaseT, 10Base2, 100BaseTX and 1000BseT are examples of
physical layer protocols. They dictate how the pulses on the wire are handled.

One of the problems with the OSI model is that there are not always good fit when it comes to mapping protocols to the seven layers. The problem
often comes in the areas btw the Session and Application layers. As an example, at which layer does does the Secure Shell (SSH) protocol live?
Is it the Session layer because it ultimately manages sessions, or is it the Presentation layer because it includes encryption mechanisms and
negotiates them? Other protocols seem to exist btw layers. ARP, for instance, is said to to operate at the Data Link layer, but it needs to know
about the network layer because it provides the bridge btw the addressing in those two layers.

However, there are places where having the model makes conceptualizing things much easier.

##TCP/IP Architecture

The way the suite of protocols used within the TCP/IP stack is described is slightly different from the way the OSI model is described. After TCP/IP
was implemented, the conceptual design of protocols was described. For this reason, the suite is sometimes referred to as model, but it may also
be referred to as an architecture, since it's a description of an as-built design rather than something conceptual. OSI is entirely conceptual since
it doesn't describe anything in particular.

The TCP/IP architecture is a much simpler design than the OSI model, which is an immediate difference and a reflection of the as-built nature of the
design as compared with the conceptual design of the OSI.

#Topologies

Some topologies are only found in certain situations. Some will be found in service provider networks, while others are more commonly found in local
area networks.

Even in cases where I'm working with virtual networks, I will find these conceptual ways of thinking about how systems are interconnected helpful. In
the end, whether I'm connecting virtual machines or containers or physical systems or some collections of all of those, I'll be working with one of
these topology models. The topology tells me how traffic flows from one system to another and what intermediary devices the communication passes
through, which will help me determine where I may be able to intercept or manipulate traffic.

##Bus Network

It consists of a single network cable to which every device on the network connects. A bus is a communication channel. There is no mediating device,
all of the computers are connected directly to one another by means of that single network cable.

##Star Network

The difference btw the bus and the star network is that there is a mediating device btw all the devices. This may be a hub, which is a repeater, or
may be a switch, which the signal will be sent to the correct port. And this is where the different layers are helpful. A switch, which is the most
common device in a star network topology, acts at layer 2 of the OSI model. It uses the MAC address to make decisions about where traffic goes.
In the case of a star network with a hub, there are the same issues as there would be with a bus network -- lots of collisions where messages sent
out on the wire run over other messages sent by someone else. A switch alleviates those issues because only traffic addressed to a system gets
sent to that system.

##Ring Network

A ring network is similar to a bus network in the sense that all of the nodes on the network appear to be connected on a contiguous network segment.
Only the system that has the token gets to talk.

##Mesh Network

If a system in a mesh network fails, there is probably another pathway to get btw one system and another. While I can connect systems together in
multiple ways in a mesh network, in spite of the orderliness that the circular design of the network shows, a couple of failures can potentially
isolate nodes in a mesh network. The way around that is to add connections. The more pathways to get from one system to another, the less chance
failure will be catastrophic, meaning communication doesn't happen. The problem with adding more connections is the resulting complexity.

##Hybrid

There are circumstances where blending multiple network topologies is the right way to go about connecting my network. One common hybrid approach
is the star-bus. If I have switches capable of 64 network connections but I have 200 users that I need to connect to my local network, I would need
to effectively add a bus into my network topology. The bus would connect all of my switches together and become a backbone for my network. Then from
each switch, I have the traditional star where all the connections come back to the switch they are connected to.

Hybrid networks are most common in the physical world where we are bound by physical networking equipment and cables.

#Physical Networking

At some point, I need to connect to the network. There are multiple components to that interaction. I need a network interface on my end. I need a
medium that is going to carry the communication. I need to have something on the other end of the communication. Because I'm not likely going to be
working at service providers or telecommunications providers as I'm doing security testing, I'm not going to worry about protocols like Frame Relay,
Asynchronous Transfer Mode or Fiber Distributed Data Interface. The protocol I will almost exclusively run across when I am talking about physical
networking is Ethernet.   

Each layer of the network stack has a different term to refer to the chunck of data encapsulated by that layer. These chunks are called protocol data
units (PDUs). The PDU at layer 2 is a frame.

##Addresing

Ethernet interfaces all have addresses. These addresses are exclusively to each network interface, and they are called MAC addresses. Because the MAC
address is hard-coded into the hardware of the interface, it is sometimes referred to as the hadware address. Since it's also the address that is used
by a physical piece of hardware, it is sometimes referred to as physical address.

The common format of a MAC address is 6 octets (8-bit bytes) separated by colons, BA:00:4C:78:57:00. The address is broken into two parts. The first
is the organizationally unique identifier (OUI). This is also called the vendor ID. The second half of the MAC address is the unique address within
the vendor ID of that interface. So, half is for the vendor, and half is ofr the card itself.

###MAC Addresses

The MAC address is represented in hexadecimal values because it's a common way to represent octets. A pair of hexadecimal values covers the range of
potential values of a byte -- 00 is 0 and ff is 255.

The MAC address is used exclusively on my local network. Any system that wants to send me anything will address it to my MAC address. I can also send
messages to every device on the network by using the broadcast address. The broadcast MAC address is ff:ff:ff:ff:ff:ff. My network interface knows
what address it has, because it's in the hardware. What this means, though, is that traffic that is in some way addressed to the interface, either
directly to its address or to the broadcast address

###Switching

MAC addresses are the cornerstone for switching. Switching is what happens when decisions about forwarding messages are made based on the physical
address. A switch is realy a multport bridge. A bridge is a device that connects two networks together, passing traffic btw them based on the
destination MAC address. Local traffic stays on one side of the bridge; traffic destined for the other side gets passed over. This does, though,
mean that the switch needs to know what MAC address lives at which port. It does this by waiting until a message comes in on each port and notices the
source address.

Because having to perform a lookup of which port to forward a message takes time, which will slow down message transmission, it's essential that the
lookup be as fast as possible. This is generally accomplished through the use of something called content-addressable memory (CAM). This means that to
look up a value, I search for it based on another value. It's easier to look up a port value by just indexing to the MAC address.

What a switch does, which is the value of switching, is make determinations about what traffic goes to which port based on the destination MAC
address. When performing security testing, acting like an attacker, it's more convenient to be able to see more traffic than that.

There are some ways around that challenge. One of them, if I have some control over the switch, is to tell the switch to mirror traffic on one port to
another port. Then, I need to have the system I'm running attacks from attached to the mirror port. Another way is to fool the switch into sending
traffic to me.

protocol processing the message. These sets of data are called headers. Each protocol has its own set of headers that get attached. The message is

###Addressing

IPv4 addresses are 4 octets long. Since each value is 8 bits, there are potential values of 0 to 255. Not all values, especially in the
first two octets, are used, however. There are some addresses that are held in reserve for various reasons. For a start, the address range
127.0.0.0 - 127.255.255.255 is reserved for loopback addresses. These are addresses that refer to the host they are assigned to. The loopback
interface ensures there is always a network interface on the system and allows for testing over a network without sending any traffic outside the
system. Commonly, the loopback address on systems is 127.0.0.1, though any address in that range could be used.

There are IP address that are used for private networks. By convetion, these address are not routable over the Internet. Most networks will do
something to block source addresses from these ranges coming into their space, since they should never be originating from the outside of a network.
The ranges for these private addresses meant to be used by any network that doesn't have public IP address, are:
10.0.0.0 - 10.255.255.255, 172.16.0.0 - 172.31.255.255 and 192.168.0.0 - 192.168.255.255.

Additionally, other address ranges are held in reserve. The range 224.0.0.0 trough 239.255.255.255 is used for multicast messages. Anything above
240.0.0.0 is also reserved and is not currently in use.

Instead of just 4 octets that are used in IPv4 IPv6 uses 16 bytes. Because an octet can be represented with two hexadecimal digits, I'll see IPv6
addresses represented in that way. There are 16 octets in an IPv6 address, the longer address I'll run across will be 32 characters.

IPv6 has three different address types. The first is unicastm which refers to a single system. Anycast addresses are groups of systems that share a
single address. A message sent to the anycast address will be delivered to just one of the hosts in the anycast group. This is commonly be the
closest address, based on routing rules. Any anycast address will have the same format as a unicast address. Multicast addresses will look like the
other addresses, but they are formatted based on the fact that they are muticast and on the application that is using the address.

###Subnets

I may need to know what addresses belong to my target based on a subnet. IP addresses are aggregated into networks using contiguous addresses. A part
of the IP address belongs to the host and a part belongs to the network. This segmentation of the addresses also helps systems to know what addresses
are local, meaning the communications stay on the local network. The way systems are told what are local networks and what are not local networks is
that a subnet mask is paired with the IP address.

To determine what portion of an IP address belongs to the network, I look at the bits that are set to 1 in the subnet mask. To better understand
this concept, let's take a look at a binary representation of a subnet mask:
11111111.11111111.11111111.10000000

Any bit position that has a 1 in its part of the network segment. Subnet masks can only have certain values: 0, 128, 192, 224, 240, 248, 252, 254 and
255. If apply binary to decimal translation to the binary adress above, I can see the subnet mask is 255.255.255.128. This means that only the last
7 bits of the last octet are used for host values. The bit representation in the last octet would be 10000000. This is where I need to start applying
the IP address to the subnet mask to get the address range.

With a subnet mask of 255.255.255.128, I have the possibilities of two address blocks, regardless of what the IP address is. I can vary the last
octet, and I am constrained because I can't change the value in the MSBP. This leaves me with the ranges of 0-127 and 128-255. Once I know what my
IP address is, I know which block I am in. Let's say my IP address is 172.20.30.42, and my netmask is 255.255.255.128. I know my address block has to
be 172.20.30.0-127 because that's the range that .42 lands in.

Another way of designating network blocks is using Classless Intern-Domain Routing (CIDR) notation. This means that rather than indicating a subnet
mask, I only get the number of prefix bits. The prefix tells me which bits are being used for the network. The subnet mask used above translates to
/25, and I would indicate the subnet with the IP address by indicating 172.20.30.42/25. 

If I want to know how many addresses belong to a particular network block, I have the CIDR notation. Often, I'll see CIDR notation hovering around the
/24 area, which is a 255.255.255.0 subnet mask and is common. If I want to know how many hosts, I just divide by 2 or multiply by 2 for every bit
change in the prefix. A network that is /24 has 256 possible values in the host portion (the last octet). If I go to /25, that means I get 128
possible values. If I go to the other direction to a /23, I double because a lost a prefix bit, so I got 512 possible values in the host portion. If
the first octet is used for the network designation and all others are used the host values, I would have all the bit positions in the first byte
filled up, which means I'm using 8 bits, leaving me with a CIDR designation of /8. Similarly, if I use the first two octets, I'm using 16 bits, so I
have a /16.

One note about subnets, though, is that there are two values that can't be used for systems. The lowest possible address in any network segment is
used for the broadcast address. In a common /24 network, the .0 becomes the network address, and the .255 is used for the broadcast. Neither of
these can be alocated for hosts.  

IPv6 makes the whole process even easier. No subnet masks are used any longer when indicating a network address. Instead, CIDR designation is used
exclusively to indicate which part is network and which is host. The same rules apply. The network portion always starts from the left. A /50
network means that the first 50 bits of the address are network designation. This leaves the remaining 78 bits (IPv6 addresses are 128 bits long) for
the host. That would be an incredible large network.
